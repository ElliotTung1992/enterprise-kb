## 二、检索与 RAG 能力增强

- **Contextual Retrieval** ⭐ **P0** — 对每个 child，embed 前用 LLM 看着 parent 生成"该段在全文语境"前缀（50–100 token），写入 `md_child_chunk.embed_text` 再 embed + BM25 索引。官方数据 retrieval failure 降 35–67%；改动只在入库管线（`MarkdownStructureIngestionService` / `MdVectorStoreService`），与现有 small-to-big 结构天然契合。
- **Self-RAG / Corrective RAG（CRAG）** — P1 — `ReactAgent` 内加 `evaluateRetrieval` 自评工具：chunks 不足 → 改写后重检索；矛盾 → 显式标注分歧。无需新框架。
- **Query 复杂度路由 + 多跳分解** — P1 — 入口加轻量分类器（可复用两层路由思路）：simple → 混合检索 + parent expansion；multi-hop / 比较类 → 拆子问题分别检索后聚合；复杂任务 → ReactAgent。
- **缓存层** — P1 — ① Embedding cache（query hash→向量，Redis TTL）② Retrieval cache（query+spaceId hash→topK chunk ids，TTL 5–15min），防热点击穿 Milvus；文档更新时按空间前缀失效。〔合并 plan.md 3.1 + 优化 9〕
- **多轮上下文压缩（Summary Memory）** — P1 — Redis 对话历史超阈值时不截断，改用 LLM 摘要压缩，兼顾上下文完整与 token 消耗。
- **Reranker 可插拔 + 升级** — P2 — 参照 `ModelProviderResolver` 抽 `RerankProvider`（DashScope / Cohere rerank-3.5 / bge-reranker-v2-m3 / Qwen3-Reranker），配置切换。**换模型前必须先有评测闭环（见 一.3）**。〔合并 plan.md 1.3 + 优化 8〕
- **向量化批处理** — P2 — child 列表分批（batch=32）并行提交 Embedding，降低向量化耗时。
- **Milvus 索引调优** — P2（规模触发）— chunk 超 50 万后 `FLAT → HNSW`（m=16, efConstruction=200），仅重建索引、无需重向量化。
- **Late Chunking（Jina 2024）** — P2 — 整篇 embed 后按 token 边界切，每个 chunk embedding 都"见过"全文。代价：换 embed → `md_kb_chunks` 重建 + 全量重 ingest。须先有评测对比。
- **Long-context fallback** — P2 — 召回总长 < 上下文窗口 30% 且置信度不高时，直接把整篇 parent 塞进 prompt。retrieval 是为省钱省延迟，非目的本身。
- **表格 RAG** — P2 — 复杂表格问答（聚合/对比/计算）现走不通；方案：表格抽出转临时 SQLite + ReactAgent 加 `queryTable` 工具，或小模型 NL→SQL。〔合并 plan.md 1.6 calculate 工具〕
- **真正视觉 RAG（替换 Noop）** — P2（先验证需求）— ColPali / ColQwen2 把页面截图当 patch 序列 embed，对含图表文档收益大；或直接用 DashScope Qwen-VL 做真 image understanding。代价：维度暴涨，存储/检索成本上升。Milvus 已支持 multi-vector。
- **GraphRAG / 实体关系层（窄场景）** — P2（先做需求验证，避免重蹈 `kb-knowledge-graph` 覆辙）— 解决纯向量拿不到的跨文档 / 全局聚合类问题（"X 公司 2024 所有事件"）。LightRAG 比 MS GraphRAG 轻量，先试；含图谱可视化（D3/Cytoscape）。〔合并 plan.md 1.2 + plan2 1.2 + 优化 10〕
- **多语言检索** — P2 — 中文专业术语分词（jieba/HanLP）、按语言路由 embedding、结果按语言相关性加权。
- **语义相似文档推荐** — P2 — 取文档主向量在 Milvus 做 topK，过滤自身，返回"相似文档"卡片。
- **Agentic 工具扩展** — P2 — 给 md `ReactAgent` 加 `getDocumentOutline`（精读目录）等工具（注：`searchByTag` 因标签体系随标准 RAG 退役而暂不适用）。
- **md 分块策略可配置** — P3 — 空间/文档级 `chunkStrategy` 字段，按类型选最合适的 child 切分方式。

## 四、安全与合规（企业刚需）

- **文档级权限 + 检索层 ACL 下沉** ⭐ **P0/P1（企业头号门槛）** — 现仅空间级 RBAC。需 ① `md_document` 级权限（READ/COMMENT/NONE）；② **权限下沉到向量召回**（Milvus 标量过滤 / partition），杜绝"检索把无权片段喂进 prompt"的越权泄露；③ 访问写 `audit_logs`。
- **Guardrail 横切层** **P1（强烈建议）** — 把 `AttackGuardService` 从客服链路抽到 `kb-common`，做 **ingest 端 + QA 端共用**的护栏：① **间接提示注入检测**（恶意文档被检索后操控 Agent，Agentic RAG 有 `readFullSection` 时危害放大）；② 输出侧 PII 过滤；③ 引用可信度校验。〔新增，三份原规划均缺〕
- **SSO / OIDC 企业登录** — P1 — Spring Security OAuth2 Client 对接 Keycloak/Auth0/飞书/企业微信，首登自动建本地用户。
- **全局限流 / 速率限制** — P1 — Bucket4j 按 userId / API Key 隔离：问答 10/min、搜索 60/min、上传 20/h（管理员更高配额），超限 429 + `Retry-After`。〔合并 plan.md 4.2 + plan2 4.2〕
- **敏感配置校验完善** — P2 — 专属 `ConfigValidator` 扩展现有 JWT 校验，启动校验 Redis 可达、至少一个 AI Provider Key 已配，fail-fast。
- **空间级 IP 访问控制** — P2 — `spaces.allowed_ip_cidrs`（JSONB）+ 拦截器校验来源 IP，适用金融/政务。
- **数据导出 / GDPR 合规** — P2 — 用户数据导出 ZIP（可携带权）+ 账户完全删除（含 Redis/PG）。
- **文档下载水印** — P3 — 下载原文叠加"下载者+时间+空间"动态水印，对截图传播追溯威慑。

## 五、工程质量与可观测性

- **集成测试覆盖 RAG 链路** ⭐ **P0/P1** — 当前**无任何自动化测试**。用 `@SpringBootTest` + Testcontainers（PG+Redis）+ mock LLM，覆盖：正常问答返回 citations、sessionId 多轮、Rerank 失败降级、空间无文档兜底。
- **结构化日志 + TraceId（MDC）** — P1 — 请求入口注入 traceId，所有日志自动携带，便于 ELK/Loki 按链路过滤（与 LangFuse trace 互补，面向运维排障）。
- **AI 调用监控指标（Micrometer）** — P1 — `kb.llm.latency` / `kb.llm.tokens.total` / `kb.llm.errors.total`（按 provider/model tag），经 `/actuator/metrics` → Prometheus/Grafana 监控成本与稳定性。
- **模型分级路由** — P1 — query rewrite / HyDE / 路由 / 评估走小模型（Qwen3-4B / Haiku 4.5），final synthesis 走大模型，省 token 省延迟。
- **异步处理进度推送** — P2 — 入库各阶段发 Spring 事件 → SSE/WebSocket 推前端，替代轮询。
- **会话列表查询优化** — P2 — `qa_sessions` 加 `message_count` 冗余字段，消除 `QaChatSessionMapper` 子查询。
- **会话自动清理** — P2 — 定时任务物理删除软删超 30 天的会话、软删 90 天未活跃会话。
- **向量 / 元数据一致性巡检** — P2 — 定期对比 `md_child_chunk` 与 Milvus `md_kb_chunks` 实际 ID，打印 diff 可选自动清理孤儿向量。
- **多节点部署支持** — P2 — 入库入口加 Redis 分布式锁（`SETNX documentId TTL`），避免多实例重复处理同一文档。

## 八、基础设施 / 规模化

- **非 Markdown 格式接入** — P1（企业刚需）— 当前**仅支持 Markdown**。策略模式按 MIME 分派 Parser：PDF / Word / Excel·CSV（表格转结构化 md）/ PPT（按页切）/ 网页爬取（URL→Playwright/Jsoup→现有管线）。
- **PostgreSQL 读写分离** — P2 — PgBouncer 主从，读路由只读副本，副本延迟 > 5s 告警。
- **Milvus 多 Collection 分区** — P2 — chunk 超 500 万按空间拆 collection，降过滤数据量。
- **配置中心化** — P2 — Nacos / Spring Cloud Config，非敏感配置动态刷新（`@RefreshScope`），敏感配置进 Vault。
- **多租户 SaaS 改造** — P2 — 数据隔离（独立 schema/库）、资源配额（`max_documents`/`max_storage_mb`）、计费（`subscription_plan` + Stripe）。
- **健康检查增强** — P2 — 自定义 `HealthIndicator` 验证 PG/Redis/Milvus/MinIO/AI Provider 下游可达，任意 DOWN 则 `/health` DOWN 触发容器重启。
