# kb-ragas 操作手册

`kb-ragas` 是企业知识库的离线 RAG 质量评测服务，基于 FastAPI + Ragas 提供 HTTP 接口，由 Java 主应用在创建 `RAGAS` 类型评测任务时调用。

## 前置条件

- 当前工作目录为项目根目录：`/Users/ganendong/Documents/workspace/claude2/enterprise-kb`
- 已安装 Docker 和 Docker Compose
- 已准备 `.env` 文件
- 真实评测模式需要配置模型 API Key，例如：

```bash
DASHSCOPE_API_KEY=你的DashScopeKey
```

如果只是验证服务启动和接口链路，可以使用 Mock 模式，不需要真实模型 Key。

## Docker 启动

`kb-ragas` 挂在 `eval` profile 下，默认不会随主服务一起启动。按需启动：

```bash
docker compose --env-file .env --profile eval up -d kb-ragas
```

查看容器状态：

```bash
docker compose --profile eval ps kb-ragas
```

查看日志：

```bash
docker compose --profile eval logs -f kb-ragas
```

停止服务：

```bash
docker compose --profile eval stop kb-ragas
```

删除容器：

```bash
docker compose --profile eval rm -f kb-ragas
```

## Mock 模式启动

Mock 模式会跳过真实 Ragas/LLM 判分，所有指标返回 `1.0`，适合本地验证评测流程。

```bash
KB_RAGAS_MOCK=true docker compose --env-file .env --profile eval up -d kb-ragas
```

也可以在 `.env` 中写入：

```bash
KB_RAGAS_MOCK=true
```

## 健康检查

服务默认暴露在本机 `8000` 端口：

```bash
curl http://127.0.0.1:8000/health
```

正常返回示例：

```json
{
  "status": "ok",
  "ragasVersion": "0.2.x",
  "mockMode": false,
  "supportedProviders": ["DASHSCOPE", "OPENAI"]
}
```

如果 `mockMode` 为 `true`，表示当前运行在 Mock 模式。

## 与主应用一起使用

先启动主应用依赖：

```bash
docker compose --env-file .env up -d
```

再启动 Ragas 服务：

```bash
docker compose --env-file .env --profile eval up -d kb-ragas
```

主应用容器内通过以下地址访问 Ragas：

```text
http://kb-ragas:8000
```

本机直接访问时使用：

```text
http://127.0.0.1:8000
```

## 触发 Ragas 评测

项目提供了封装脚本：

```bash
ADMIN_TOKEN=你的管理员JWT \
API_URL=http://127.0.0.1:8081 \
DATASET=regression \
TARGET_SERVICE=MdQnAService \
scripts/run-ragas-eval.sh
```

常用参数：

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| `ADMIN_TOKEN` | 无 | 必填，管理员 JWT |
| `API_URL` | `http://127.0.0.1:8081` | Java 主应用地址 |
| `DATASET` | `regression` | 评测数据集名称 |
| `TARGET_SERVICE` | `MdQnAService` | 被评测服务 |
| `RAGAS_GATE_MODE` | `warn` | 门禁模式：`warn` / `soft` / `hard` |
| `POLL_SECONDS` | `10` | 轮询评测结果间隔 |

可选的 Agentic RAG 评测示例：

```bash
ADMIN_TOKEN=你的管理员JWT \
TARGET_SERVICE=MdAgenticQnAService \
scripts/run-ragas-eval.sh
```

## 直接调用 kb-ragas API

健康检查：

```bash
curl http://127.0.0.1:8000/health
```

提交评测任务：

```bash
curl -X POST http://127.0.0.1:8000/evaluations \
  -H "Content-Type: application/json" \
  -d '{
    "items": [
      {
        "caseId": "00000000-0000-0000-0000-000000000001",
        "question": "什么是企业知识库？",
        "answer": "企业知识库用于集中管理和检索企业内部知识。",
        "contexts": ["企业知识库集中存储文档、知识片段和问答数据。"],
        "groundTruth": "企业知识库用于集中存储、管理和检索企业内部知识。"
      }
    ],
    "judgeProvider": "DASHSCOPE",
    "judgeModel": "qwen-max",
    "embeddingProvider": "DASHSCOPE",
    "embeddingModel": "text-embedding-v3"
  }'
```

返回中的 `jobId` 可用于查询结果：

```bash
curl http://127.0.0.1:8000/evaluations/你的jobId
```

## 本地 Python 启动

不使用 Docker 时，可以直接在 `kb-ragas` 目录运行：

```bash
cd kb-ragas
python3.11 -m venv .venv
source .venv/bin/activate
pip install -e .
uvicorn kb_ragas.app:app --host 0.0.0.0 --port 8000
```

Mock 模式：

```bash
KB_RAGAS_MOCK=true uvicorn kb_ragas.app:app --host 0.0.0.0 --port 8000
```

## 常见问题

### 1. `/health` 访问失败

先确认容器是否启动：

```bash
docker compose --profile eval ps kb-ragas
```

再查看日志：

```bash
docker compose --profile eval logs kb-ragas
```

### 2. 真实评测失败并提示 API Key 未配置

确认 `.env` 中存在对应 Key：

```bash
grep -E "DASHSCOPE_API_KEY|OPENAI_API_KEY" .env
```

修改 `.env` 后重启：

```bash
docker compose --env-file .env --profile eval up -d --force-recreate kb-ragas
```

### 3. Java 主应用连接不上 kb-ragas

Docker Compose 内部地址应使用：

```text
http://kb-ragas:8000
```

本机命令行或浏览器访问才使用：

```text
http://127.0.0.1:8000
```

### 4. `context_recall requires groundTruth`

`context_recall` 指标要求每条评测样本都有 `groundTruth`。解决方式：

- 给 `eval_cases.expected_json` 补充 `referenceAnswer`
- 或在调用 `/evaluations` 时移除 `context_recall` 指标
